# Building and testing

This document describes how to build the Manjaro-targeted Assistant package, how the NVIDIA source data is obtained, how the MHWD packages consume that data, and how to run the test suites.

The Assistant source and the Manjaro packaging repository are separate concerns:

- `megvadulthangya/nvidia-driver-assistant`, branch `manjaro-upstream`, contains the Python implementation and its PKGBUILD.
- `megvadulthangya/PKGBUILDs`, branch `develop`, contains the Manjaro package recipes for `nvidia-driver-assistant`, `mhwd`, `mhwd-db` and the NVIDIA driver packages.

The Assistant source code is not patched by the MHWD package. MHWD receives one of two C++ integration patches in its own PKGBUILD.

## 1. Components

| Component | Source | Package / output |
|---|---|---|
| NVIDIA decision engine | `megvadulthangya/nvidia-driver-assistant` (`manjaro-upstream`) | `nvidia-driver-assistant` |
| MHWD application | Manjaro `mhwd` source pinned by the PKGBUILD, plus one Assistant integration patch | `mhwd` |
| MHWD profile database | Manjaro `mhwd-db` source pinned by the PKGBUILD | `mhwd-db` |
| NVIDIA PCI ID lists | Generated by the NVIDIA utils PKGBUILDs using the Assistant | `mhwd-nvidia`, `mhwd-nvidia-580xx`, `mhwd-nvidia-470xx`, `mhwd-nvidia-390xx` split packages |
| Kernel-module flavour wrapper | `show-driver` in the Assistant repository | `/usr/bin/nvidia-recommended-driver` |

The Assistant can also generate and audit a 340xx `.ids` file. The current Manjaro package set does not provide the corresponding 340xx driver/profile, but the program's 340xx parser and ID features remain present.

## 2. Build prerequisites

The PKGBUILDs declare their build dependencies. Common tools include:

| Tool | Use |
|---|---|
| `base-devel` | `makepkg` and standard package build tools |
| `git` | Source repository retrieval |
| `curl` | NVIDIA DEB and supportedchips downloads |
| `libarchive` | Extracting the upstream DEB payload |
| `gzip` | DEB payload handling |
| `python` | Assistant runtime and validation scripts |
| `python-pyyaml` | YAML configuration loading |
| `cmake` | Building MHWD |
| `patch` | Applying the selected MHWD integration patch in the Manjaro-targeted package |

Install the usual build tools first:

```shell
sudo pacman -S --needed base-devel git
```

`makepkg -s` installs the package-specific dependencies declared by each PKGBUILD when they are available in the configured repositories.

## 3. Build `nvidia-driver-assistant`

### 3.1 Clone the target branch

```shell
git clone --branch manjaro-upstream \
  https://github.com/megvadulthangya/nvidia-driver-assistant.git
cd nvidia-driver-assistant
```

### 3.2 Version calculation

The PKGBUILD calculates `pkgver()` from two parts:

1. The latest `nvidia-driver-assistant` DEB version found in NVIDIA's Ubuntu 24.04 CUDA repository.
2. The short Git commit hash of the checked-out Assistant source.

The resulting package version therefore identifies both the upstream NVIDIA data-package version and the Assistant source revision. It is not necessary to manually copy the upstream DEB version into `pkgver=`.

### 3.3 NVIDIA DEB extraction

During `prepare()`, the PKGBUILD:

1. Retrieves the current `nvidia-driver-assistant` DEB from NVIDIA's CUDA repository index.
2. Extracts the DEB payload.
3. Makes `supported-gpus.json` and the NVIDIA EULA available for packaging.

The Python implementation remains the code from this Git branch. The DEB supplies the upstream data asset and licence material; it does not replace the fork's Python modules.

### 3.4 Download the five supportedchips documents

The PKGBUILD determines the current NVIDIA documentation versions for:

- latest 6xx;
- 580;
- 470;
- 390;
- 340.

Each version can be pinned temporarily through its corresponding override variable in the PKGBUILD:

```bash
_6xx_version_override=""
_580_version_override=""
_470_version_override=""
_390_version_override=""
_340_version_override=""
```

An empty value enables automatic version discovery from NVIDIA's driver directory index. A non-empty value pins a specific version and is validated against that driver's version pattern. Overrides are intended for deliberate testing or recovery when automatic discovery cannot be used.

The document URL has this structure:

```text
https://us.download.nvidia.com/XFree86/Linux-x86_64/<version>/README/supportedchips.html
```

The downloaded files are:

```text
supportedchips.html
supportedchips580.html
supportedchips470.html
supportedchips390.html
supportedchips340.html
```

### 3.5 Validate and install the documents

The PKGBUILD copies the documents into the Python package data directory and runs the shipped parser's `validate_all_documents()` function against the five files. It checks for usable data in each generation before the package can be created.

A missing or unparseable document stops the build. This is intentional: silently shipping an incomplete NVIDIA ID database would create a package whose recommendation or MHWD data could be stale.

### 3.6 Build and install

```shell
makepkg -si
```

The package installs:

- the `nvidia-driver-assistant` command;
- the `nvidia_driver_assistant` Python modules;
- the YAML configuration files and five supportedchips documents;
- the extracted `supported-gpus.json` data;
- the NVIDIA EULA;
- `nvidia-recommended-driver`, provided by the `show-driver` compatibility wrapper;
- README and configuration documentation under `/usr/share/doc/nvidia-driver-assistant/`.

Runtime dependencies are `python` and `python-pyyaml`.

### 3.7 Verify the package

```shell
nvidia-driver-assistant --simulate-gpu 750 --mhwd
# Expected: closed

nvidia-driver-assistant --simulate-gpu 4070 --mhwd
# Expected: open

nvidia-driver-assistant --generate-ids 340 | head -n 2
```

To confirm that all five documents are available to the installed package:

```shell
python - <<'PY'
from nvidia_driver_assistant.supported_chips import validate_all_documents
result = validate_all_documents()
for branch in ("6xx", "580", "470", "390", "340"):
    print("%s: %d IDs" % (branch, len(result[branch])))
PY
```

## 4. MHWD NVIDIA ID package generation

The NVIDIA utils PKGBUILDs retain their MHWD split-package outputs. The old shell helper is no longer the source of the IDs in the updated 390xx, 470xx, 580xx and latest package recipes. Instead, each package invokes the Assistant generator.

The relevant commands are:

```bash
nvidia-driver-assistant --generate-ids 390 > "${pkgdir}/var/lib/mhwd/ids/pci/nvidia-390xx.ids"
nvidia-driver-assistant --generate-ids 470 > "${pkgdir}/var/lib/mhwd/ids/pci/nvidia-470xx.ids"
nvidia-driver-assistant --generate-ids 580 > "${pkgdir}/var/lib/mhwd/ids/pci/nvidia-580xx.ids"
nvidia-driver-assistant --generate-ids latest > "${pkgdir}/var/lib/mhwd/ids/pci/nvidia.ids"
```

The split package names remain because MHWD's package metadata and database still depend on those package interfaces. The implementation that creates the ID contents is now the Assistant's parser and generator.

The Assistant also retains:

```bash
nvidia-driver-assistant --generate-ids 340
```

This command is valid and can generate the 340xx list. The current Manjaro package set does not include a 340xx driver or matching official MHWD profile, so this software capability is not the same as an available Manjaro package.

## 5. Build the patched `mhwd` package

The Manjaro package recipe is in the PKGBUILDs repository under `extra/mhwd/`.

### 5.1 Select the integration mode

The PKGBUILD contains two alternative patch files and a mode variable:

```bash
NVIDIA_ASSISTANT_MODE="corrective"
```

Accepted values:

- `authority` — the Assistant's system-level `--mhwd-config` result drives NVIDIA profile selection.
- `corrective` — MHWD selects by its normal priority order first, then the Assistant validates the branch for each NVIDIA PCI Device ID and corrects a mismatch when a matching profile exists.

Only one patch is selected and applied. The patches must never be applied together.

### 5.2 Patch files

| Mode | Patch |
|---|---|
| `authority` | `0001-mhwd-nvidia-assistant-integration.patch` |
| `corrective` | `0002-mhwd-nvidia-assistant-corrective.patch` |

The Manjaro-targeted PKGBUILD declares GNU `patch` as a build dependency and applies the selected patch from the MHWD source root with:

```bash
patch --batch --forward -Np1 -i "${_patchfile}"
```

The PKGBUILD pins the MHWD source revision so the patch is applied against the source context for which it was prepared. If the MHWD source commit changes, the patch must be checked and rebased as needed.

### 5.3 Build

From the `extra/mhwd/` package directory in the PKGBUILDs checkout:

```shell
makepkg -s
```

The build applies the selected patch in `prepare()`, configures MHWD with CMake and builds it. The `NVIDIA_ASSISTANT_MODE` variable changes which integration patch is applied; it does not modify the Assistant source code.

### 5.4 Verify

After installing the package, the binary should contain the Assistant integration strings:

```shell
strings /usr/bin/mhwd | grep -E 'nvidia-driver-assistant|NVIDIA Driver Assistant'
```

For an end-to-end check on a test system, run the normal MHWD auto-configure path and inspect which config is selected. Do not use a package installation test on a production system unless the selected transaction is intended.

## 6. Build `mhwd-db`

The current Manjaro `mhwd-db` package recipe pins a Manjaro source commit and installs the PCI configuration database under `/var/lib/mhwd/db/`.

The package dependencies include the Manjaro NVIDIA ID split packages for the currently available package set:

- `mhwd-nvidia`;
- `mhwd-nvidia-580xx`;
- `mhwd-nvidia-470xx`;
- `mhwd-nvidia-390xx`.

It also depends on `nvidia-driver-assistant`, which is called by the NVIDIA profile configuration during installation. The current package dependency set does not include a 340xx profile package.

Build the `mhwd-db` package from its directory in the PKGBUILDs checkout:

```shell
makepkg -s
```

## 7. Testing

### 7.1 Supportedchips parser tests

```shell
PYTHONPATH=. python3 -m unittest discover \
  -s tests -p 'test_supported_chips_parser.py' -v
```

These cover the modern latest/580 documents, old-format 470/390/340 tables, subsystem ID extraction and legacy-section boundaries.

### 7.2 MHWD ID tests

```shell
PYTHONPATH=. python3 -m unittest discover \
  -s tests -p 'test_mhwd_ids.py' -v
```

These cover each supported generator branch, including 340, output format, invalid/empty data and read-only audit behaviour.

### 7.3 Original and extended suites

```shell
PYTHONPATH=. python3 tests/run --suite test_nvidia_driver_assistant.py
PYTHONPATH=. python3 moretests/run --suite test_nvidia_driver_assistant.py
```

The `run` wrappers use `umockdev-wrapper` to simulate hardware. These tests do not require the corresponding physical NVIDIA devices.

### 7.4 GitHub Actions

The `compatibility-validation.yml` workflow:

1. installs the Python, YAML and umockdev test dependencies;
2. downloads all five NVIDIA supportedchips documents;
3. validates the documents through the parser;
4. runs parser and MHWD ID tests;
5. runs the original and extended suites;
6. runs an informational compatibility matrix that does not fail the workflow.

CI validation is useful for detecting parser or logic regressions. It does not replace testing on actual NVIDIA hardware and a real Manjaro MHWD installation.

## 8. Scope and package availability

The Assistant code retains 340xx support, and the build validates and installs the 340 supportedchips document. The current Manjaro package set and MHWD database start at 390xx. Do not interpret the 340 parser, generator or audit support as evidence that Manjaro currently ships a 340xx package or MHWD profile.

Likewise, the presence of the `mhwd-nvidia*` split packages is intentional: the package interface remains required by the MHWD configuration database even though the ID list is now generated by the Assistant rather than by the retired shell helper.
